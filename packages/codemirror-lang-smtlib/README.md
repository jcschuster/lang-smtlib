# codemirror-lang-smtlib

[SMT-LIB](https://smt-lib.org) language support for [CodeMirror 6](https://codemirror.net/):
a Lezer parser generated from the concrete syntax (Appendix B) of the SMT-LIB Standard,
Version 2.7, release 2026-09-09 (recorded in `package.json` under `smtlib.reference`), with
highlighting, folding, Lisp-style indentation and completion of command names, reserved
words and predefined keywords.

```js
import {EditorView, basicSetup} from "codemirror"
import {smtlib} from "codemirror-lang-smtlib"

new EditorView({extensions: [basicSetup, smtlib()], parent: document.body})
```

`smtlib()` reads scripts. `smtlibLanguage.configure({top})` reads the other parts of the
standard instead: `"Responses"` (solver output, any number of `<general_response>`),
`"TheoryFile"` (`<theory_decl>`) or `"LogicFile"` (`<logic>`).

Nodes are named after the productions of Appendix B (`Command`, `Term`, `Sort`,
`QualIdentifier`, `GetValueResponse`, ...). A command outside the standard, such as z3's
`check-sat-using`, is a `GenericCommand` and not an error. Reserved words and command names
are tokens named by their text; so are the keywords and predefined symbols that Appendix B
uses as terminals (`:print-success`, `true`, `sat`). A parenthesised S-expression is a
`List`, comments are `LineComment`, string literals `String`.

What the tests show: every production of Appendix B is reachable in the grammar; the test
cases cover every command, term form and literal class; the fixtures in the repository are
scripts that z3 and cvc5 accept and parse without errors, as do the answers both solvers gave
to them. Solver responses are ambiguous without the command they answer; which reading the
tree shows is described in `gen/CONFLICTS.md` of the repository.

Two deviations from Appendix B, both listed in `spec/README.md` of the repository:
`(push)` and `(pop)` without a numeral, and hexadecimal indices such as `(_ char #x41)`, as
the official Strings theory writes characters. Other solver extensions that reuse a
standard command name with other arguments are errors.

Limits: Lezer cuts its parse stack at a fixed depth, so deep nesting gets error nodes:
from about 550 nested `let`s, 1400 nested applications or 2800 nested S-expression lists.

## Generated and hand-written files

In the [lang-smtlib](https://github.com/jcschuster/lang-smtlib) repository:

- Generated by `gen/bnf2lezer.mjs` (`pnpm generate`): `src/smtlib.grammar` from
  `spec/smtlib-2.7.bnf`, `spec/smtlib-2.7.lex` and `gen/overlay.grammar`, and `src/words.ts`
  from the word lists of the `.lex` file.
- Hand-written: the two spec files (written from Appendix B), `gen/overlay.grammar`
  (top rules, the skip rule, `GenericCommand`, preferences among ambiguous responses, a
  token precedence; each entry explained in `gen/CONFLICTS.md`), `src/highlight.ts`,
  `src/index.ts` and `src/smtlib.grammar.d.ts`.
